# Slicer

Программа для численного исследования динамических систем: карты притяжения,
динамических режимов и периодов, бассейны притяжения, показатели Ляпунова и траектории.
Вычислительное ядро написано на C++, API — на Python, интерфейс — на React.
Также доступны бифуркационные деревья, анимации фазовых портретов и экспорт SVG, HDF5 и GIF.

## Запуск

Установите и запустите Docker с Compose v2: Docker Desktop на Windows (с WSL 2)
и macOS, либо Docker Engine с плагином Compose на Linux.
Для Windows используйте Linux containers. Python, Node.js и компилятор на хосте не нужны.
На первую сборку нужны интернет, несколько гигабайт свободного места и время на загрузку образов.
Рекомендуется выделить Docker не менее 6 ГБ памяти.

В терминале из корня скачанного проекта выполните:

```sh
docker compose up -d --build
```

Откройте [Slicer](http://localhost:5173). Вход и настройка учётных записей не нужны.
Каждый пользователь запускает собственный экземпляр; расчёты и загруженные системы
доступны в этом экземпляре. Сервисы опубликованы только на локальном компьютере.

В Explorer выберите систему и тип расчёта, задайте параметры и нажмите **Запустить**.
Начните с небольшой сетки, чтобы проверить запуск. На странице Computations
можно посмотреть состояние, отменить расчёт и скачать результат; на Systems —
скомпилировать собственную систему из исходного кода C++ (есть пример и справка).

## Windows: первый запуск

На Windows программа собирается в Linux-контейнерах Docker Desktop.
Устанавливать Visual Studio, CMake, Python, Node.js и библиотеки HDF5 в Windows не нужно:
все зависимости устанавливаются при сборке контейнеров.

1. Установите WSL 2. Если WSL ещё нет, откройте PowerShell **от имени администратора**,
   выполните команду ниже и перезагрузите компьютер:

   ```powershell
   wsl --install
   ```

   Для уже установленного WSL доступно обновление: `wsl --update`.
   Подробности: [инструкция Microsoft](https://learn.microsoft.com/en-us/windows/wsl/install).

2. Установите и запустите [Docker Desktop для Windows](https://docs.docker.com/desktop/setup/install/windows-install/).
   Используйте WSL 2 backend и Linux containers. Дождитесь запуска Docker Engine.
   Актуальные требования к версии Windows и виртуализации приведены на странице установки Docker.

3. Скачайте репозиторий через **Code → Download ZIP** и распакуйте архив,
   например в `C:\Projects\slicer`. Git для этого не нужен.
   Откройте PowerShell в распакованной папке **с файлом compose.yaml**.
   Вложенная папка из ZIP может называться `slicer-main`.

4. Проверьте Docker и запустите проект:

   ```powershell
   docker compose version
   docker info
   docker compose up -d --build
   ```

5. Откройте **http://localhost:5173**. Первый запуск дольше последующих:
   скачиваются образы и зависимости, компилируется C++ ядро.
   Если страница ещё недоступна, проверьте `docker compose ps` и дождитесь запуска сервисов.

Эта же команда запуска работает в macOS и Linux. Исходники приложения копируются
в образы; каталоги с установленными зависимостями с компьютера пользователя не нужны.
В репозитории для shell-скриптов и SQL закреплены окончания строк LF через `.gitattributes`.

### Если на Windows не запускается

| Симптом | Что проверить |
| --- | --- |
| `docker` не найден | Установлен ли Docker Desktop; после установки откройте новый терминал. |
| Нет соединения с Docker Engine | Запущен ли Docker Desktop и завершился ли запуск движка. |
| Ошибка WSL / виртуализации | Обновите WSL; проверьте включение аппаратной виртуализации по инструкции Docker. |
| `no configuration file provided` | Перейдите в папку, где лежит `compose.yaml`. |
| `port is already allocated` | Освободите занятый порт или измените его проброс в `compose.yaml`. |
| Ошибка скачивания образа или пакета | Проверьте доступ Docker к интернету и повторите команду сборки. |
| Компилятор завершён с `Killed`, код 137 | Проверьте доступную Docker/WSL память и свободное место; закройте тяжёлые приложения. |
| Страница открылась, расчёт завершился ошибкой | Посмотрите `docker compose logs --tail=100 api worker`. |

Запуск полного проекта без Docker непосредственно в Windows не является основным
способом запуска: тогда зависимости ядра, API, БД и хранилища нужно устанавливать отдельно.

## Управление

```sh
docker compose ps                 # состояние сервисов
docker compose logs --tail=100    # последние сообщения
docker compose stop              # остановить, сохранив контейнеры и данные
docker compose up -d              # запустить повторно
docker compose down              # удалить контейнеры, сохранив данные
```

Расчёты, HDF5-артефакты и плагины сохраняются в именованных Docker-томах проекта.
Команда `docker compose down -v` удаляет также все эти данные.
После изменений исходного кода снова выполните `docker compose up -d --build`.

Если порт занят, остановите другое приложение или измените левую часть соответствующего
проброса порта в `compose.yaml`. По умолчанию используются 5173, 8000, 5432, 9000 и 9001.
Если Docker недоступен, проверьте, что Docker Desktop или Docker Engine запущен.
При ошибке расчёта проверьте `docker compose logs api worker`.

По умолчанию worker ограничен 2 CPU, 4 ГБ памяти и часом на расчёт.
Эти настройки относятся к заданиям из Computations. Деревья и фазовые анимации
рассчитываются через API: для них нет прикладного лимита числа шагов и таймаута;
большие расчёты могут потребовать много времени и памяти.
При необходимости создайте `.env` в корне проекта с нужными значениями:

```dotenv
WORKER_CPU_LIMIT=2
WORKER_MEMORY_LIMIT=4g
RUN_TIMEOUT_SECONDS=3600
```

Применить настройки: `docker compose up -d`.

## Бифуркационные диаграммы неподвижных точек

В Explorer рядом с **Дерево** расположена кнопка **Бифуркационная диаграмма**,
доступная для одномерных и двумерных отображений. Нажмите её, выберите на карте
концы отрезка A и B, затем задайте область поиска в фазовом пространстве.
Окно настроек и результата устроено так же, как у дерева: параметры A/B можно
отредактировать, результат выгрузить в SVG и HDF5. Если меняется один параметр,
он подписан по горизонтали; если несколько — используется координата `t` от 0 до 1.
Решаются уравнения `F(x,p) - x = 0` методом Ньютона
с уменьшением шага при росте невязки. Начальные приближения берутся из регулярной
сетки, включая границы, и из решений предыдущего значения параметра.

Диаграмма показывает мелкие точки на светлом поле: по горизонтали параметр,
по вертикали координата неподвижной точки. Цвет обозначает её полный тип:
`Stable Node` — устойчивый узел (зелёный), `Unstable Node` — неустойчивый узел (оранжевый),
`Saddle` — седло (фиолетовый), `Stable Focus` — устойчивый фокус (синий),
`Unstable Focus` — неустойчивый фокус (красный). Эта классификация используется для 2D.
В 1D используются подписи `Stable` (асимптотически устойчивая точка) и `Unstable`
(неустойчивая); в данных им соответствуют типы `attracting` и `repelling`.
При `|μ| ≈ 1` результат обозначается `Nonhyperbolic` серым цветом: односторонняя
полуустойчивость требует нелинейного анализа и автоматически не определяется.
Легенда включена и в SVG. Старые одномерные результаты с типами `stable_node` и
`repeller_node` при чтении API показываются как `attracting` и `repelling`,
с исходным обозначением в `stored_type`; сохранённый HDF5 не переписывается.
Выбор точки или раскрытие «Точки и мультипликаторы» показывает координаты, невязку,
мультипликаторы и тип (узел/фокус для 2D). Мультипликаторы — собственные значения
`DF`; производные вычисляются пятиузловой центральной разностью.
Если `abs(abs(μ)-1) <= stability_tolerance`, точка считается негиперболической.
Условия `μ ≈ +1`, `μ ≈ −1` и комплексная пара `|μ| ≈ 1` отмечаются в таблице;
это кандидаты на бифуркации, без уточнения параметра события и проверки нормальной формы.

Расчёты сохраняются в Computations и открываются в окне Explorer по
`/?fixed_points=<UUID>`. API: `POST /runs` с `calculation_type=fixed_point_diagram`,
полными наборами параметров `start` и `end` и границами `state_min`/`state_max`;
чтение — `GET /runs/{id}/fixed-points?offset=0&limit=1000` (пагинация по срезам).
CLI-пример после сборки ядра:

```sh
core/build/slicer run --job core/examples/henon_fixed_points.json \
  --output /tmp/henon-fixed-points.h5 --systems-dir core/build/systems
```

В `core/examples/chialvo_fixed_point_types.json` приведён срез Chialvo по `c`
с `a=0.9`, `b=0.2`, `I=0.05`, на котором встречаются все пять типов точек.

Метод находит в том числе неустойчивые точки. Полнота поиска не гарантируется:
в 1D интервалы дополнительно разделяются стационарными точками невязки `F(x)-x`,
корни локализуются по смене знака и уточняются методом Ньютона. Это уменьшает
зависимость от бассейнов сходимости начальных приближений, но конечное сканирование
всё ещё может пропускать тесно расположенные или быстро осциллирующие корни.
Для проверки полноты
увеличивайте плотность сетки и проверяйте область поиска. Уменьшение шага Ньютона
удерживает приближения внутри заданной области; производные могут потребовать
вычисления отображения за её границей. При `μ = +1` матрица `DF-I` вырождается;
счётчик несошедшихся запусков показан отдельно и не означает отсутствия корней.
При негиперболичности линейная классификация не определяет нелинейную устойчивость.
Алгоритм не продолжает ветви по длине дуги и не ищет циклы периода больше одного.
Ограничения: до 1000 срезов, 32 начальных приближений на ось, 64 корней на срез,
50000 точек всего и `steps × (seeds_per_axis^dimension + 64) × max_iterations <= 2000000`.
Превышение числа корней завершает расчёт ошибкой, чтобы не сохранять усечённый результат.

## Структура

| Каталог | Назначение |
| --- | --- |
| `core/` | C++ ядро, встроенные системы и тесты |
| `api/` | FastAPI, управление расчётами и компиляция систем |
| `worker/` | Выполнение заданий и сохранение результатов |
| `web/` | Веб-интерфейс |
| `schemas/` | Схемы данных и реестры расчётов и систем |
| `deploy/` | Инициализация БД и хранилища систем |

Встроенные системы: `henon`, `chialvo`, `universal2d`. Загруженные пользователем системы хранятся в локальном Docker-томе и не переносятся через Git.
На новом компьютере собственные отображения нужно загрузить на странице Systems.

API: [документация](http://localhost:8000/docs).
MinIO: [консоль](http://localhost:9001), логин `minio`, пароль `minio123`.
PostgreSQL: `localhost:5432`, база, пользователь и пароль — `slicer`.
Это конфигурация для локального запуска.

## Разработка и тесты

Для разработки ядра см. [core/README.md](core/README.md).
При локальной разработке API используйте Python 3.11+:

```sh
cd api
python -m venv .venv
```

Активируйте окружение: `.venv\Scripts\Activate.ps1` в Windows PowerShell
или `source .venv/bin/activate` в macOS/Linux. Затем:

```sh
pip install -e ".[dev]"
pytest -q
```

Проверка интерфейса (Node.js 22):

```sh
cd web
npm ci
npm run build
```

Предшественник проекта — [PhaseSlicer](https://github.com/FFG99/PhaseSlicer).
